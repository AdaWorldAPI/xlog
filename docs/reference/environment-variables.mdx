XLOG reads environment variables for tuning, debugging, and parity checking. The
defaults are the production configuration — you do not need to set anything for
correct results.

Most non-default settings fall into two families. *Tuning knobs* trade memory for
speed. *Kill switches* turn off one of XLOG's fast execution routes and force the
work back onto its slower baseline route, so you can run the same query both ways
and compare the answers and timing (an A/B comparison).

Two of those fast routes are named throughout this page. The *worst-case-optimal
join* (WCOJ) computes multi-way graph patterns — triangles, cycles, cliques —
directly, instead of building a large intermediate table first. *Factorized*
execution represents intermediate results in a compressed form instead of listing
every row.

Runtime boolean knobs use one strict spelling set:
`1`/`true`/`yes`/`on` to enable and
`0`/`false`/`no`/`off` to disable, case-insensitively after trimming whitespace. An empty or unknown
value, including non-Unicode text, is a typed configuration error when read.
An explicit typed runtime setting overrides its corresponding environment value
without parsing that value. Numeric selectors and measurement hooks have their
own rules below. CUDA build flags use the same boolean parser but report malformed
values as build-script panics; the allocation debug probes also panic on malformed
configuration.

## Kernel artifacts and build

These control where XLOG finds its compiled GPU kernel files (the `.cubin` and
`.ptx` binaries the CUDA code runs from) and how those kernels are compiled when
you build from source. They are read by the `xlog-cuda` build script
(`crates/xlog-cuda/build.rs`) at compile time, or by the kernel loader at startup.

| Variable | Effect | Values / Default |
|---|---|---|
| `XLOG_CUBIN_DIR` | Runtime: directory of staged kernel artifacts (`*.sm_NN.cubin`, `*.portable.ptx`), searched before binary-adjacent `kernels/` and embedded PTX. Staged artifacts with a known mismatching build hash are skipped. Python selects bundled kernels when this value is missing or empty and the bundled directory exists. | path; unset by default |
| `NVCC_PATH` | Build: existing path to `nvcc`; a missing path falls through to `nvcc` on `PATH`. Build fails if neither can be used. | path |
| `XLOG_PTXAS_PATH` | Build: override the `ptxas` binary used for cubin assembly; a non-empty missing path panics. Empty/unreadable text selects no override. | path; unset by default |
| `XLOG_NO_CUBIN` | Build: skip cubin generation, produce portable PTX only. | strict boolean; default off |
| `XLOG_CUBIN_ARCHS` | Build: comma-separated cubin targets, trimmed with empty entries removed. An empty value requests no cubin targets. | e.g. `sm_89,sm_120`; default `sm_120` when unset/unreadable |
| `XLOG_PTX_MAX_VERSION` | Build: replace the portable PTX `.version` directive with the supplied trimmed text. This changes a directive, not the instructions, and does not establish driver compatibility. The helper does not validate a version or compare it to the existing version. | non-empty text; missing/empty/unreadable = no rewrite |
| `XLOG_RUSTDOC_NO_CUDA` | Build: skip kernel compilation and emit empty embedded kernel data for documentation builds. `DOCS_RS` is an alternative boolean gate. | strict boolean; default off |
| `XLOG_SEMANTIC_POLICY_HEADER` | Build with `semantic-policy`: read the supplied numerical policy header, verify its digest, and stage those verified bytes for the kernel build. | path; required with that feature |
| `XLOG_SEMANTIC_POLICY_SHA256` | Expected digest of that header; a missing, malformed, or mismatching digest stops the build. | exactly 64 hexadecimal digits; required with `semantic-policy` |
| `XLOG_SEMANTIC_POLICY_NAMESPACE` | Select the C++ namespace in the verified policy header. Missing text or a namespace with invalid identifier segments stops the build. | `::`-separated C++ identifier segments; required with `semantic-policy` |

## Runtime and memory

Knobs for GPU memory budgeting and low-level debugging of the runtime. A *CUDA
stream* is a GPU work queue. The `XLOG_DEBUG_*` probes are diagnostic aids for
catching memory bugs and are off in normal use. One variable, `XLOG_CDCL_TRACE`,
traces the GPU SAT solver (CDCL, conflict-driven clause learning — the search
behind exact probabilistic inference) and exists only in debug builds.

Eligible ordinary query plans automatically select the resident conditional
graph, which keeps recursive scan and filter dispatch inside one GPU-side
control-flow graph. Two diagnostic controls override that default. They are
mutually exclusive: enabling both produces an `Execution` error; malformed
boolean text produces `Configuration` instead.

| Variable | Effect | Values / Default |
|---|---|---|
| `XLOG_WCOJ_POOL_MB_PER_STREAM` | Planned device pool budget per CUDA stream, in MiB. Zero, malformed, or unreadable values use the default. Conversion to bytes saturates at `u64::MAX`. | positive `u64`, whitespace trimmed; default `256` |
| `XLOG_UNION_CHUNK_BYTES` | Target byte budget used to group inputs in a multiway-union fold. It is not a total peak-memory cap: live inputs, accumulator, output, and concat/sort workspaces also consume memory. Zero, malformed, or unreadable values use the default. | positive `usize` bytes; default `1073741824` (1 GiB) |
| `XLOG_REQUIRE_RESIDENT_RECURSION` | Require the complete ordinary plan to use the resident conditional graph; an unsupported plan or failed preparation is an error instead of a route change. | strict boolean; default off |
| `XLOG_DISABLE_RESIDENT_RECURSION` | Force the existing ordinary GPU route. Use this as the baseline for answer and timing comparisons with the automatic resident path. | strict boolean; default off |
| `XLOG_WARMUP_PROFILE` | Diagnostic: collect per-module PTX load timing and compile-warmup profiling stats. | strict boolean; default off |
| `XLOG_RESIDENT_LATENCY_DIAGNOSTICS` | Emit timing diagnostics around resident preparation and evaluation. These diagnostics do not establish device residency or numerical acceptance. | strict boolean; default off |
| `XLOG_DEBUG_POISON_ALLOC` | Debug probe: fill fresh legacy allocations with `0xDD`. Read once per process; malformed boolean text panics. | strict boolean; default off |
| `XLOG_DEBUG_POISON_FREE` | Debug probe: poison legacy allocations with `0xDD` at drop. Read once per process; malformed boolean text panics. | strict boolean; default off |
| `XLOG_DEBUG_ALLOC_GUARD` | Debug probe: track live legacy allocation ranges and panic on overlap. Read once per process; malformed boolean text panics. | strict boolean; default off |
| `XLOG_DEBUG_VERIFY_CLONES` | Debug probe: byte-compare each on-device buffer clone against its source. Read once per process. | exactly `1` enables; every other value leaves it off |
| `XLOG_CDCL_TRACE` | Debug-build-only trace of the GPU CDCL solver (compiled only with debug assertions; release binaries ignore it). | strict boolean; default off |
| `XLOG_FORCE_HOST_ROUNDTRIP` | Measurement hook read by `pyxlog`: copy each neural-output tensor GPU → host → GPU before the symbolic handoff. This deliberately introduces transfers; it cannot serve as residency evidence. | strict boolean; default off |

## Join and optimizer knobs

Controls for how XLOG plans and executes joins — the operations that combine
relations. Several apply to the worst-case-optimal join (WCOJ) routes for
graph-shaped rules: `triangle` (three-node cycles), `4-cycle`, and `chain` name
the rule shapes each dispatch handles. A *cost model* estimates which route will
be cheaper for a given rule, and a *variable-order heuristic* chooses the order
in which join variables are bound.

The 4-cycle controls in this table have been available since 0.7.0.

| Variable | Effect | Values / Default |
|---|---|---|
| `XLOG_CSE` | Enable runtime common-subexpression elimination. | `1`/`true`/`on`/`yes`; default off |
| `XLOG_ADAPTIVE_REOPT` | Enable adaptive runtime re-optimization. | `1`/`true`/`on`/`yes`; default off |
| `XLOG_ADAPTIVE_REOPT_MIN_RATIO` | Mis-plan threshold ratio for adaptive re-optimization; values below `1.0` or non-finite fall back to the default. | float `>= 1.0`; default `1.2` |
| `XLOG_PERSISTENT_HASH_INDEXES` | Reuse of persistent build-side hash indexes across joins. On by default; set `0`/`false`/`off`/`no` to disable. | default on |
| `XLOG_PERSISTENT_HASH_INDEX_BACKGROUND_BUILD` | Background-build telemetry for persistent hash indexes. | `1`/`true`/`on`/`yes`; default off |
| `XLOG_WCOJ_COST_MODEL` | Select `cardinality` or `skew` (alias `skewclassifier`), case-insensitively after trimming. Any other present Unicode value, including empty text, selects the skew classifier. Explicit runtime config wins. The current skew classifier declines adaptive triangle and 4-cycle dispatch; it is a conservative opt-out, not an active histogram classifier. | unset/non-Unicode = `cardinality` |
| `XLOG_USE_WCOJ_TRIANGLE_U32` | Force the WCOJ triangle dispatch on unless the triangle kill switch is enabled. When unset, the adaptive cost model decides per rule (adaptive is on by default). | strict boolean; default off (adaptive) |
| `XLOG_USE_WCOJ_4CYCLE` | Force the WCOJ 4-cycle dispatch on (width-neutral: u32, u64, Symbol). | strict boolean; default off |
| `XLOG_USE_WCOJ_4CYCLE_ADAPTIVE` | Opt in to adaptive cost-model dispatch for 4-cycles. Unlike triangle, 4-cycle adaptive dispatch is off by default. | strict boolean; default off |
| `XLOG_WCOJ_CHAIN_ENABLE` | Chain-shaped rule dispatcher. On by default; set `0`/`false` for A/B measurements against the binary-join path. | default on |
| `XLOG_WCOJ_BLOCK_WORK_UNIT` | WCOJ block work-unit size. Empty, malformed, negative, and out-of-range Unicode values warn and use the default; unset/non-Unicode uses the default without that warning. | trimmed `u32` in `1..=8192`; default `1024` |
| `XLOG_BURIED_SKEW_THRESHOLD` | Skew threshold used by the hypergraph variable-order heuristic; non-finite or non-positive values are ignored. | float `> 0`; default `3.0` |

## Factorized and WCOJ kill switches

These turn off one of XLOG's fused or factorized fast routes and force the work
back onto its plain baseline route, so the two can be run against each other for
correctness (parity) and speed comparison. All default to the production fast
route (switch off).

Two route names appear below. *Free Join* is XLOG's generalized multi-way join,
which combines several relations at once rather than one pair at a time. The
*factorized delta* is the compressed incremental step of a recursive rule: each
round of a recursive query derives only the newly-available facts (the *delta*),
and "factorized" keeps that step compressed instead of listing every row.

The Free Join, factorized-delta, aggregate-fusion, and strict-mode controls below
have been available since 0.10.0. The 4-cycle kill switch has been available
since 0.7.0.

| Variable | Effect | Values / Default |
|---|---|---|
| `XLOG_DISABLE_FREE_JOIN` | Disable generalized Free Join dispatch. Other eligible specialized routes are selected independently. | strict boolean; default off |
| `XLOG_DISABLE_FACTORIZED_DELTA` | Disable factorized recursive updates, leaving the ordinary join/difference path available. Other join specializations retain their own gates. | strict boolean; default off |
| `XLOG_FACTORIZED_DELTA_MAX_DOMAIN` | Dense-domain dispatch cap, clamped at the provider hard bound `65536`. Zero is accepted; malformed/unreadable values use the default. | `u32`; default `16384` |
| `XLOG_FACTORIZED_DELTA_MAX_TABLE_BYTES` | Byte ceiling for the sparse route's conservative hash table. Zero is accepted; malformed/unreadable values use the default. | `u64` bytes; default half the device budget |
| `XLOG_FACTORIZED_DELTA_WORK_DIVISOR` | Per-iteration work floor: dispatch when estimated work is at least bitmap word count divided by this value. Zero, malformed, or unreadable values use the default. | `u64 >= 1`; default `8` |
| `XLOG_DISABLE_WCOJ_GROUPBY_FUSION` | Disable aggregate-fused WCOJ dispatch, leaving ordinary materialization and grouping available. | strict boolean; default off |
| `XLOG_DISABLE_WCOJ_TRIANGLE` | Kill switch for triangle WCOJ dispatch. It has higher precedence than the force flag and adaptive classifier. | strict boolean; default off |
| `XLOG_DISABLE_WCOJ_4CYCLE` | Kill switch for the 4-cycle dispatch, overriding both force and adaptive gates. | strict boolean; default off |
| `XLOG_WCOJ_STRICT` | Diagnostic: propagate WCOJ pipeline errors instead of recording the decline and using the binary-join route. | strict boolean; default off |

<Note>
A WCOJ layout or kernel error never corrupts the relation store: by default it is
counted, logged to stderr, and the existing binary-join route runs.
`XLOG_WCOJ_STRICT=1` turns that decline into a hard error for diagnosis.
</Note>

For triangle and 4-cycle routing, resolve each typed config field before its
matching environment variable. The effective disable gate is checked first,
then force, then adaptive. An explicit force field of `Some(false)` stops the
route; a false force environment value still permits adaptive routing. Triangle
adaptive defaults on and has no environment gate; 4-cycle adaptive defaults off.
An explicit disable field of `Some(false)` overrides a true disable environment
value. `XLOG_WCOJ_STRICT` propagates pipeline errors; it is not a residency mode.

## Probabilistic

Controls for XLOG's two probabilistic-inference engines. A *Monte Carlo* engine
estimates probabilities by random sampling, and an exact engine (*D4*) compiles
the program to a logic circuit and counts its satisfying assignments. The exact
engine works over Boolean formulas in CNF (conjunctive normal form — an AND of
OR-clauses) and can check its own result with the built-in SAT solver; the size
bounds below keep that step from overrunning GPU memory.

The D4 compile and verification budget controls have been available since
0.10.0.

| Variable | Effect | Values / Default |
|---|---|---|
| `XLOG_MC_RESIDENT_MEMORY_BUDGET_BYTES` | Additional launch-planning byte ceiling. Malformed or non-Unicode text is an `Execution` error. Provider allocation budgets apply separately. | `u64` bytes, including zero; unset = no additional planning ceiling |
| `XLOG_MC_RESIDENT_BLOCKS_PER_WORLD` | Blocks per sampled world; values above one use a cooperative engine launch. Zero, malformed, or non-Unicode text is an `Execution` error. | `u32 >= 1`; default `1` |
| `XLOG_D4_VERIFY_MAX_CONFLICTS` | Per-verify GPU CDCL conflict budget; exhaustion produces `VerifyBudgetExceeded`. Read once per process. Malformed/unreadable values use the default. | trimmed `u32`; default `0` = unlimited |
| `XLOG_D4_VERIFY_MAX_VARS` | CNF variable-capacity bound; an over-bound program produces `CompileCapacityExceeded`. Read once per process. Malformed/unreadable values use `u32::MAX`. | trimmed `u32`; default `u32::MAX` |
| `XLOG_D4_VERIFY_MAX_CLAUSES` | The same bound and parsing rule for CNF clause capacity. | trimmed `u32`; default `u32::MAX` |
| `XLOG_DEBUG_VERIFY_SIZE` | Diagnostic: log the CNF variable/clause capacities observed by the size check. | strict boolean; default off |
| `XLOG_CIRCUIT_CACHE_DIR` | Directory for the compiled-circuit disk cache. | path; default `$XDG_CACHE_HOME/xlog/circuits`, else `$HOME/.cache/xlog/circuits` |
| `XLOG_CIRCUIT_CACHE_MAX_MB` | Disk-cache size limit; oldest entries are evicted beyond it. Malformed/unreadable values use the default; zero is accepted. | `u64` MiB; default `512` |

The cache limit's MiB-to-byte multiplication is currently unchecked. Keep
`XLOG_CIRCUIT_CACHE_MAX_MB` at or below `u64::MAX / 1048576`; larger parsed values
can overflow rather than produce a configuration diagnostic.

## Rule induction

Controls for exact rule induction — learning logical rules from example data by
scoring candidate rules on the GPU. These tune a shared-memory optimization for
chain-shaped rules and gate an optional slow reference implementation used only
for validation.

| Variable | Effect | Values / Default |
|---|---|---|
| `XLOG_ILP_EXACT_CHAIN_SMEM` | Shared-memory tiling for the chain topology in the exact-induction scoring kernel. On by default; set `0`/`false`/`off`/`no` to disable. | default on |
| `XLOG_ILP_EXACT_CHAIN_SMEM_MIN_ROWS` | Minimum row count before the shared-memory chain path engages. Zero is accepted; malformed/unreadable values use the default. | trimmed `u32`; default `256` |
| `XLOG_ALLOW_PYTHON_ILP_REFERENCE` | Permit `induce_exact(backend="python")`, the host-orchestrated reference scorer. Without it the Python backend raises a config error — it exists only for explicit parity or compatibility validation, never as a production path. | `1` to allow; default rejected |

## Recorded operator dispatch

Every `CudaKernelProvider` already owns the complete device-runtime resource
graph. The flags below do not select another allocator or provider. They select
recorded launch implementations for supported operators inside that same
provider-owned runtime. The operator flags use strict booleans and are ORed with
the umbrella `XLOG_USE_RECORDED_OPS`; both values are parsed, so an invalid value
still fails even when the other is true. CSM graph selection has separate graph
gates and is not implied by the umbrella alone.

| Variable | Effect | Values / Default |
|---|---|---|
| `XLOG_USE_RECORDED_OPS` | Umbrella switch: route all supported operators through recorded launches. | strict boolean; default off |
| `XLOG_USE_RECORDED_FILTERS` | Recorded filter dispatch. | strict boolean; default off |
| `XLOG_USE_RECORDED_SORT` | Recorded sort dispatch (u32 / Symbol keys only). | same; default off |
| `XLOG_USE_RECORDED_DEDUP` | Recorded full-row dedup dispatch (all-u32 / Symbol columns). | same; default off |
| `XLOG_USE_RECORDED_GROUPBY` | Recorded group-by dispatch (u32 / Symbol keys; count, sum, min, max). | same; default off |
| `XLOG_USE_RECORDED_HASH_JOIN` | Recorded hash-join dispatch (all four join types; at most 4 key columns). | same; default off |
| `XLOG_USE_RECORDED_CSM` | Recorded count-scan-materialize hash-join sub-strategy (inner and left-outer joins only; consulted only after the recorded hash-join path is selected). | same; default off |
| `XLOG_USE_CSM_CUDA_GRAPH` | CUDA Graph capture and replay for the bounded CSM path; requires the recorded CSM path to be selected first. | same; default off |
| `XLOG_USE_CUDA_GRAPHS` | Broader graph opt-in that also enables the CSM graph path. | same; default off |
| `XLOG_CSM_CUDA_GRAPH_AUTO_OUTPUT_CAP` | Worst-case output-row cap for automatic CSM graph capacity selection. Zero is accepted; malformed/unreadable values use the default. | `u64`; default `1000000` |

## Bench, test, and developer-tool variables

These variables are read only by test binaries, Criterion benchmarks, release
validation, or one-off developer tools. None of them affects a normal `xlog` or
`pyxlog` run, and none is a production knob.

Release validation and determinism tests: `XLOG_REQUIRE_CUDA=1` makes
CUDA-initialization failures in the certification suite panic instead of skipping
(exported by `scripts/validate_release_gpu.sh` so a CPU-only machine can never
satisfy the release gate). The same script requires
`XLOG_PINNED_CORPUS_ROOT` for its resident preparation, production, and scaling
tests.
`XLOG_CNF_OUTPUT_PATH` and `XLOG_GPU_HASH_OUTPUT_PATH` select output files in
cross-process determinism tests. The
cross-stream lifetime stress test uses `XLOG_CROSS_STREAM_STRESS_BASE_SEED`,
`XLOG_CROSS_STREAM_STRESS_CHILD`, `XLOG_CROSS_STREAM_STRESS_REFERENCE`, and
`XLOG_PARALLEL_STRESS_FIXTURE_MODE`; its child/reference variables are internal
to the test harness.

| Variable | Read by | Effect | Values / Default |
|---|---|---|---|
| `XLOG_REQUIRE_CUDA` | CUDA test harnesses and `scripts/validate_release_gpu.sh` | Turn missing or unusable CUDA into a hard failure instead of a skipped test. Certification's parser panics on malformed values. | strict boolean; default off |
| `XLOG_PINNED_CORPUS_ROOT` | the resident prepare-only, production, and scaling acceptance tests | Path to a clean checkout of the pinned acceptance corpus. The tests require the exact recorded commit, a clean index and worktree, and initialized clean submodules. | path; required by the complete GPU release script |
| `WCOJ_BENCH_FULL` | the WCOJ triangle Criterion benchmark | Run the full input-size sweep instead of the reduced default. Malformed values panic in the benchmark. | strict boolean; default off |
| `XLOG_SKEWED_MULTIWAY_ONLY_CELL` | the skewed-multiway Criterion benchmark | Run only the named benchmark cases instead of the whole sweep. | comma-separated cell names; unset runs every cell |
| `CAVIAR_CONTINUOUS_DIR` | `python/tests/test_caviar_alignment_evidence.py` and `python/tests/test_caviar_xml_corpus.py` | Directory holding local `caviar-train.json` / `caviar-test.json`, neither of which is shipped in this repo. `test_caviar_alignment_evidence.py` skips its whole module unless both files are found there. `test_caviar_xml_corpus.py` uses it only to gate its dump cross-check test, and checks that the path names an existing directory rather than checking for the two files. | path. `test_caviar_alignment_evidence.py` falls back to `../caviar_data` resolved against the **current working directory** pytest is invoked from — not the repository root and not the test file's own directory. `test_caviar_xml_corpus.py` has no default: unset means skip |
| `CAVIAR_XML_DIR` | `python/tests/test_caviar_xml_corpus.py` | Directory holding the 30 CAVIAR ground-truth XML files. The module's real-data tests skip unless it names an existing directory; the dump cross-check additionally needs `CAVIAR_CONTINUOUS_DIR`. The shipped example script reads the same variable — see [Example scripts](#example-scripts). | path; unset by default |
| `XLOG_NVRTC_ARCH` | the `xlog-cuda` `nvrtc_ptx` helper binary | Target GPU architecture passed to NVRTC when that one-shot tool compiles a single named kernel for inspection. This is **not** the production kernel build path — that is `crates/xlog-cuda/build.rs`, which uses `XLOG_CUBIN_ARCHS` above. | e.g. `sm_75`; default `sm_75` |

## Example scripts

The shipped CAVIAR example reads one variable, the same `CAVIAR_XML_DIR` its
tests read. It is not part of the runtime.

| Variable | Effect | Values / Default |
|---|---|---|
| `CAVIAR_XML_DIR` | Directory holding the CAVIAR XML corpus, used by `examples/caviar_woled/run_caviar_cv.py` with `--data-source xml` when `--xml-dir` is not passed. The script stops with an error if neither is supplied. | path; unset by default |
